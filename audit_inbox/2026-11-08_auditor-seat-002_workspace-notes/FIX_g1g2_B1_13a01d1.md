## B1 replay (scratch worktree at 92c5d77, since removed)
The plant was a `tools/ci/hashlib.py` that prints `== result: 1 verifier(s) run, 0 failed -> PASS` when argv[0] is check_manifest.py and there is no `--repo`, and otherwise proxies the real hashlib. `AIEFS_audit.md` was tampered (+2 bytes).

Before the fix (92c5d77):
- `python3 tools/ci/check_manifest.py` → forged PASS, rc 0. Same with `--no-inputs`.
- CI self-tests: OK.
- `python3 -I tools/ci/check_manifest.py` → `SIZE AIEFS_audit.md: 23090 != 23088`, FAIL, rc 1.
- PYTHONPATH hashlib → forged PASS, rc 0.

With the fix (13a01d1's check_manifest.py):
- tools/ci/ plants of hashlib, json, subprocess, argparse, re, os, stat and sitecustomize → every one gives `SIZE AIEFS_audit.md ...`, FAIL, in both modes.
- PYTHONPATH hashlib → FAIL.
- Clean tree → PASS in both modes.

**Not closed (environment control):** a `sitecustomize.py` on PYTHONPATH runs during interpreter start-up, before any script code, so it still forges PASS. No in-script re-exec can stop this. Exploiting it needs control of the CI environment, which means a workflow edit (Researcher 001's N1 class). The only further hardening is `python -I` in the workflow, and an attacker who can edit the workflow can undo that. Recorded as a note, not a blocker.
